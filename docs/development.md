# 开发指南

本页面向修改扩展的人。架构理由见 [architecture.md](architecture.md)；“为什么不生效”的排查步骤见 [debugging.md](debugging.md)。

## 开始前

1. 阅读根目录 `AGENTS.md` 的硬约束。
2. 运行 `npm install`，再运行 `npm run dev`。开发端口必须是 3212。
3. 保留 `.dev-profile/`，它包含本地知乎登录态。

每次改动至少运行：

```bash
npm run compile
npm test
```

需要交付或确认打包内容时，再运行 `npm run build`。

## 新增或调整开关

开关的唯一配置在 `src/switches/index.ts`，页面 CSS 的唯一位置是 `src/styles/content.css`。新增一项时按以下顺序执行：

1. 在 `SWITCHES` 添加稳定的 kebab-case `id`。已发布的 id 不可改名，否则旧设置会被清理。
2. 填写名词短语 `title`、说明目标或结果的 `desc`、`pages`、`region`、`default` 与 `anchors`。未经登录态实测的锚点标为 `unverified`。
3. 如使用 `suppressedBy`，父子必须同一 `region` 且不能形成环。面板会递归展示该关系。
4. 在 `content.css` 添加同 id 的 `[data-zf-<id>]` 规则和“已核实 + 日期”注释。页面选择器不得出现在其他文件；注释中不得出现 `*/`。
5. 运行类型检查与测试；随后在登录态下验证锚点、开关、级联和命中数。确认后将锚点状态改为 `verified`。

无需修改 popup 或 content 入口。它们从注册表读取开关和级联结果。

## 修改页面样式

- JS 只能在 `<html>` 上挂或摘 `data-zf-<id>`；不得改写知乎 DOM、自动点击或注入页面 UI。
- 选择语义类或结构关系，例如 `:has()` 与相邻兄弟；不要依赖知乎的哈希类名。
- 阅读页正文列保持 654px、列宽保持 694px；首页和热榜信息流列保持 860px；专栏沿用 654px。
- 改版后优先更新 CSS 注释中的核实日期和注册表锚点，而不是在入口脚本里补页面特判。

## 人工冒烟检查

在受影响的知乎页面确认：

1. 开关能隐藏和恢复对应元素。
2. 父开关接管子开关时，面板状态与实际页面一致。
3. 当前页命中数符合“关掉它会露出几处”；没有目标时显示“无目标”。
4. 刷新和 SPA 页面切换后，快照会在首帧应用，随后与同步设置一致。

## 支持边界

以下项目暂不支持，除非获得明确需求与稳定锚点：首页侧栏的付费咨询推广和推荐关注卡、专栏的关于作者与整列侧栏，以及 `hide-app-banner` 尚未在真实页面验证的三个锚点。

## 提交范围

一个开关对应一个提交，提交信息注明锚点和核实日期。只暂存本次修改的文件；不要处理其他正在进行的改动。
