# 开发指南

本页面向修改扩展的人。架构理由见 [architecture.md](architecture.md)；“为什么不生效”的排查步骤见 [debugging.md](debugging.md)。

## 开始前

1. 阅读根目录 `AGENTS.md` 的硬约束。
2. 运行 `npm install`，再运行 `npm run dev`。开发端口必须是 3212。
3. 保留 `.dev-profile/`，它包含本地知乎登录态。

每次改动至少运行：

```bash
npm run compile
npm test
```

需要交付或确认打包内容时，再运行 `npm run build`。

## 新增或调整开关

开关的唯一配置在 `src/switches/index.ts`，页面 CSS 的唯一位置是 `src/styles/content.css`。新增一项时按以下顺序执行：

1. 在 `SWITCHES` 添加稳定的 kebab-case `id`。已发布的 id 默认不改名，否则旧设置会被清理；破坏性重构确需改名时，随 minor 版本升级一并发布，并在提交说明里列出丢弃的旧键。
2. 填写名词短语 `title`、说明目标或结果的 `desc`、`pages`、`region`、`default` 与 `anchors`（只服务命中数）。顶栏紧凑开关格用可选 `short` 作短标签，缺省回退 `title`。
3. 如使用 `suppressedBy`，父子必须同一 `region` 且不能形成环。面板以嵌套行展示该关系，父项生效时子项禁用并提示接管来源。
4. 在 `content.css` 添加同 id 的 `[data-zf-<id>]` 规则和“已核实 + 日期”注释。页面选择器不得出现在其他文件；注释中不得出现 `*/`。
5. 运行类型检查与测试；随后在登录态下验证锚点、开关、级联和命中数。

无需修改 popup 或 content 入口。它们从注册表读取开关和级联结果。

### 数值调节项

需要可调数值时，在开关上增加 `range: { min, max, step, default, unit }`，并在 `content.css` 用 `var(--zf-<id>, <default><unit>)` 消费。popup 会自动渲染滑块，数值存 `params` 而非布尔 `overrides`；`sanitizeParams` 负责 clamp 与 step 对齐。

数值项默认即生效，滑块上限应不小于目标容器的自然宽度（图片宽度取 720px，大于正文列 704px），让“拖到最大 = 不限制”成立，不要再叠加启用开关。content 入口会把值写到 `<html>` 的 `--zf-<id>`，页面切换时自动移除。

## 修改页面样式

- JS 只能在 `<html>` 上挂或摘 `data-zf-<id>`；不得改写知乎 DOM、自动点击或注入页面 UI。
- 选择语义类或结构关系，例如 `:has()` 与相邻兄弟；不要依赖知乎的哈希类名。
- 不覆盖知乎的自然列宽：首页/热榜主栏 784px、文本卡 704px，问题/回答/专栏正文列 704px。收起侧栏时只做居中，另把问题头收窄到 704px 与正文同轴；需要约束的尺寸写死 px，不用视口百分比。
- 改版后优先更新 CSS 注释中的核实日期和注册表锚点，而不是在入口脚本里补页面特判。

## 人工冒烟检查

在受影响的知乎页面确认：

1. 开关能隐藏和恢复对应元素。
2. 父开关接管子开关时，面板状态与实际页面一致。
3. 当前页命中数等于本页目标处数；没有目标时显示“无目标”；切到非当前页时不显示命中数。面板亮暗表示显示/隐藏，与存储层的 hide 语义相反。
4. 刷新和 SPA 页面切换后，快照会在首帧应用，随后与同步设置一致。
5. 图片宽度滑块调到 160/320/720 时，首页信息流正文与点开卡片后的文章封面、问题/回答与专栏正文图随之变为对应 px（窄容器内不超过容器宽）；720 等于原文宽度；刷新与 SPA 切换后保持。另点开一张正文图，确认查看浮层不被缩小。

## 支持边界

以下项目暂不支持，除非获得明确需求与稳定锚点：首页侧栏的付费咨询推广卡。

专栏目录页（`/column/c_xxx`）与专栏文章页共用「专栏页」，本页只吃到全局类开关（顶栏一组、广告位、悬浮按钮、热榜卡）；目录页自身的专栏头和文章列表项还没有专属开关与锚点，列宽也未实测。要做之前先在登录态页面盘点类名，不要在入口加页面特判。

## 提交范围

一个开关对应一个提交，提交信息注明锚点和核实日期。只暂存本次修改的文件；不要处理其他正在进行的改动。
